功能 01

丢一份文档进去，自动变成题库

不用一题一题手工录入。选择 DOCX 或 JSON 文件，猫卷自动识别题目、选项、答案与解析，生成可编辑的预览，确认后入库。

  • DOCX / JSON 双通道：Word 文档直接导入，也支持结构化 JSON 题库
  • AI 智能分块：长文档按题目边界切块，并发解析，不阻塞界面
  • 可视化校对：入库前逐题预览、编辑、删除，AI 打的知识点标签一并保留
  • 开放格式：题库可导出为标准 JSON，在同学之间自由流转
⚙ 技术实现
用什么
Dart Isolate 独立线程做文档解析；archive 解包 DOCX（本质是 ZIP）、xml 解析 word/document.xml 提取段落文本；AI 解析走 OpenAI 兼容的 Chat Completions 接口。
怎么做
① 题目边界感知切块：识别 1.、第N题、（1） 等题号起始行，把完整题目装进一个块（上限 2000 字），切点永远落在题目之间，绝不切断一道题；② 3 路并发 worker 池解析各块，结果按块号稳定回收；③ 逐级降采样重试：输出超限时把 token 上限从 8192 → 4096 → 2048 逐级下调重试；④ 截断 JSON 抢修：解析失败时从尾部回溯补 } 闭合，挽救前面已完整的题目；⑤ 失败的块会明确报出原因，不谎报"解析完成 0 题"。

功能 02

题库是一个个独立的文件，随你管理

多题库并存、按需勾选、随时导出。每个题库的题量、正确率一目了然，重名会自动编号避免混淆。

  • 多库并存：考研、执医、规培各自成库，可单独或组合刷题
  • 导出即分享：一键导出 JSON 题库文件，同学导入即可用
  • 级联删除：删题库时相关题目、记录、批注一并清理，不留脏数据
⚙ 技术实现
用什么
SQLite（sqflite）作为唯一数据源，题目/会话/记录分表存储，外键开启 PRAGMA foreign_keys=ON 实现级联删除。
怎么做
题库以 question_banks 表为根，题目挂在 questions.bank_id 外键上；删除题库时由数据库外键级联清理题目、作答记录、错题、复习卡与批注，避免出现"孤儿数据"污染统计。导出时组装 {format, name, count, questions} 结构，带格式标记 maojuan-quiz-questions，导入端校验通过才入库，形成闭环。

功能 03

三种模式，对应三种学习状态

正常刷题用来检测、练习模式用来模考、背题模式用来快速过题。同一套题目，三种节奏。

  • 正常刷题：答完即判，立刻看解析，答对自动跳下一题
  • 练习模式：限时（15–120 分钟）或不限时，答题卡漫游、统一交卷批改
  • 背题模式：高亮正确答案、不记统计，适合考前快速过一遍
  • 数量自由：10/20/30/50/80/100/全部/自定义
  • 断点续刷：中途退出进度保留，下次从首页继续，不丢一道题
⚙ 技术实现
用什么
Flutter 单页承载三种模式（QuizMode 枚举驱动），抽题走 SQL ORDER BY RANDOM() 随机；会话与题序落库到 quiz_sessions + session_questions 表。
怎么做
① 抽题时数量下推给 SQL 用 LIMIT 完成，避免全量取回再截断；② 会话落库保存题目顺序，实现断点续刷的精确还原；③ 练习模式答案先收集在内存 Map、零落库，交卷时才批量判定写库；④ 背题模式 persistSession:false，全程不产生任何统计污染；⑤ 限时归零先关弹窗防竞态，再自动交卷。

功能 04

七种题型，每种都有对应的判定逻辑

不只是选择题。判断题、填空题、名词解释、简答题、问答题都能练，而且判分不是简单的字符串相等。

  • 单选 / 多选 / 判断：多选忽略顺序与分隔符；判断题自动归一化各种写法
  • 填空：按空拆分，逐空去标点比对
  • 名解 / 简答 / 问答：语义包含匹配，答到关键点即可
  • 重新作答：答错可重做，更新原记录而不新增，不污染刷题量
⚙ 技术实现
用什么
统一的 judgeAnswer 判定函数按题型分派，刷题与练习共用同一套逻辑，保证判分一致。
怎么做
① 判断题归一化：不正确/不对/错误/×/X/F/FALSE → 错，正确/对/√/T/TRUE → 对，其中否定词优先匹配，避免"不对"被当成"对"；② 多选题：按中英文逗号、顿号、分号、空格拆分后转大写去重，集合比较忽略顺序；③ 填空题：按分号拆空、逐空去标点比对，空数不一致直接判错；④ 主观题：去标点后做双向包含匹配，且对 3 字以内答案（如"细胞壁"）改为精确相等并豁免"过短判错"。

功能 05

不是给你答案，是教你题眼怎么破

每一道题的解析都按"题眼破题法"四步拆解，模拟一个老师在旁边讲题的过程，而不是甩一段标准答案。

  • 抓题眼，定性：第一句点出决定答案的关键数据或特征
  • 理逻辑，拆选项：讲透正确项推理，也说明错误项为什么错
  • 指坑点，防踩雷：精准指出最容易掉的陷阱与鉴别点
  • 给结论，划重点：一句口诀或大白话总结得分要点
  • 只看一次的钱：解析本地缓存，同一道题不重复消耗 Token
⚙ 技术实现
用什么
DeepSeek deepseek-chat（OpenAI 兼容接口），请求走 json_object 结构化输出、temperature 0.1 保证解析稳定；结果落 ai_cache 表，question_id 唯一。
怎么做
Prompt 固定输出五段结构（答案 / 题眼 / 解析 / 避坑指南 / 一句话记忆），把"讲题方法论"固化进提示词而不是靠模型自由发挥；调用前先查缓存，命中直接返回、零 Token 消耗；异常或错误响应（isAiError）绝不入缓存，防止一次断网把"请求失败"永久固化成解析结果；解析支持一键重新生成。

功能 06

看不懂？直接追问，像聊天一样

解析里哪一句没懂，就接着问。你的提问和 AI 的回答以对话气泡呈现，一问一答都留在题目旁边，下次打开还在。

  • 对话式交互：你的提问在右、AI 回复在左，一路聊到底
  • 按题保存：每道题的追问历史独立存储，换题不串、重启不丢
  • 富文本回复：支持加粗、列表、表格，长解析也读得清楚
  • 自动滚到底：内容变长时输入框跟随对话下移，不用手动找
⚙ 技术实现
用什么
独立数据表 follow_up_messages（question_id / role / content / created_at），按题查询升序最多 50 条；回复渲染用自研轻量富文本渲染器。
怎么做
① Prompt 里带上原题、选项、正确答案、已有解析与你的追问，让 AI 在上下文里作答；② 用户消息先即时上屏再等回复，交互不卡顿；③ 发送中防重复提交；④ 切题竞态保护：追问过程中切到别的题，回复仍会按原题号入库，不会插到当前题上；⑤ 渲染器自己解析加粗、列表、Markdown 表格，替换掉对第三方 Markdown 包的依赖。

功能 07

错题不是收藏起来，是排好期再练

错题本内置 FSRS-5 间隔重复算法：按你的遗忘曲线计算每道错题的下次复习时间，到期的才出现，避免"反复刷已经会的"。

  • 自动排期：答完自动更新复习卡，不需要你手动设置"几天后再看"
  • 只显示到期：打开错题本，看到的都是此刻该复习的题
  • 反应时间参与评分：答得又快又对 → 判定为"简单"，间隔拉得更长
  • 知识点标签云：按知识点聚合错误，一眼看出薄弱章节，可一键专项复习
  • 薄弱诊断：结合统计数据生成学习建议
⚙ 技术实现
用什么
FSRS-5 算法（19 个默认权重），目标记忆保留率设 0.9；复习卡存 fsrs_cards 表，以 question_id 为主键。
怎么做
① 遗忘曲线建模：可提取性按 R = exp(ln(0.9) × 已过天数 / 稳定性) 计算，据此更新每张卡的"稳定性"与"难度"两个核心参数；② 行为自动评分：答错 → Again；答对且 <3 秒 → Easy；3–10 秒 → Good；≥10 秒 → Hard，用户无需手动打分；③ 间隔计算：下一次间隔约为 稳定性 × (9/难度 − 1) 天，向上取整至少 1 天，稳定性与难度分别 clamp 在合理区间防极端值；④ 改判补记：修正历史作答时，在同一事务内同步更新复习卡，保证算法状态与记录一致。

努力看得见，进步有据可查

刷题量、正确率、学习时长、连续打卡、错题分布……所有数据在本地实时计算，用图表讲清楚你的学习状态。

⚙ 技术实现
用什么
趋势图与热力日历均用 Flutter CustomPainter 自绘（无图表库依赖），数据由 SQL 聚合查询在设备端完成。
怎么做
① 双 Y 轴自绘：左轴题量、右轴正确率，柱形与分层折线叠画，支持点击气泡查看单日明细、按周分页；② Y 轴自适应：轴上限按数据最大值动态计算（下限 20），避免刷题量小时柱子被压成一条线；③ 热力图色阶：按当日题量分四档着色，今天高亮描边、假期置灰；④ 统计口径统一排除"隐藏记录"与"模拟数据"，保证真实作答才进入指标。
功能 09

纸上怎么划重点，屏幕上就怎么划

直接在题目上圈关键词、划重点、写推导。笔迹按题目保存，切题、重启、换设备都不会丢。

  • 三种笔型：细笔 / 普通笔 / 荧光笔，支持压感调宽
  • 四色可选：红、蓝、绿、黑，颜色记忆偏好
  • 橡皮与选择：整笔擦除，或选中笔迹后平移 / 删除
  • 跨设备适配：手机、平板、桌面尺寸不同，笔迹位置保持一致
⚙ 技术实现
用什么
CustomPaint + Listener 捕获指针事件；笔迹数据存 question_annotations 表，复合主键 (question_id, device_id)。
怎么做
① 坐标归一化：所有点位换算成 0–1 的相对坐标存储，因此同一份笔迹在任意屏幕尺寸下都能还原到相同位置；② 曲线平滑：用二次贝塞尔中点法把采样点连成顺滑曲线（而非折线），笔帽笔接用圆角；③ 流畅度优化：点距过近的采样点直接抽稀丢弃，压感取均值映射到 0.5–1.5 倍笔宽；④ 按设备隔离：批注以 (题目, 设备) 为键，多端同步时各端笔迹共存不互相覆盖；⑤ 数据损坏时按"无批注"降级，不阻塞刷题。

功能 11

手机、平板、电脑，同一份题库接着刷

大屏不是简单拉伸。窗口够宽时界面自动变成左右并排布局，题区、解析、列表各就各位。

  • 自适应断点：平板、宽屏各有独立布局策略
  • 双栏布局：宽屏下题目与解析左右并排，减少滚动
  • 内容限宽：大屏不会把文字拉成超长行，阅读舒适
  • 拖动即重排：桌面端改变窗口大小，布局实时响应
⚙ 技术实现
用什么
LayoutBuilder 实时监听可用宽度；断点参照 Material 窗口尺寸分类；同一套 Flutter 代码构建 Android 与 Windows。
怎么做
① 两档断点：最短边 ≥600dp 判定为平板、窗口宽 ≥840dp 判定为宽屏布局；② AdaptivePair 组件在可用宽 ≥900 时自动左右并排、否则上下堆叠，拖动窗口即时重排；③ 内容限宽：普通内容最大 640、宽屏二级页最大 1200，底部弹窗最大 480，避免大屏出现超长文本行；④ 页面用统一的自适应容器居中限宽，无需每个页面各自处理。
功能 12

同一个 Wi-Fi 下，手机和平板自动对上

没有云账号，也能多设备用。两台设备连同一个 Wi-Fi，自动发现彼此并交换题库与刷题进度，全程在局域网内完成。

  • 自动发现：同一 Wi-Fi 下设备自动出现在列表里，无需填 IP
  • 一次请求双向同步：互相交换快照并合并，双方都拿到对方数据
  • 智能合并：新增内容按全局 ID 去重，已有的按时间取新
  • 批注互不覆盖：各设备的笔迹共存，谁的批注都不丢
  • 不经过云：数据只在你的两台设备之间直接传输
⚙ 技术实现
用什么
纯 Dart dart:io 实现，无第三方网络框架：UDP 三通道发现 + 本机 HttpServer 交换数据；Android 侧申请 MulticastLock 保证能收到广播包。
怎么做
① 三通道发现互为兜底：子网单播扫描（属出站流量，不受入站防火墙限制，最可靠）+ 多播组 + 子网广播；② 信标是 JSON，带应用魔数、协议版本、设备 ID 与端口，收到对方信标即单播应答，实现双向可见；③ 设备按 ID 去重、超时自动剔除；④ 一次请求完成双向同步：POST 快照的同时响应本机快照；⑤ 合并策略：题库/题目/会话/作答记录按全局 uid upsert，批注与错题按"（题目, 设备）"隔离共存绝不覆盖，外键按 uid 映射到本地自增 ID；⑥ 自动同步带冷却时间，也可手动"立即同步"。

你的数据，真正属于你

没有账号体系，不采集个人信息。题库、错题、进度、批注全部存在本机 SQLite 数据库里，一键导出备份，换手机原样恢复。

  • 本地存储：全部数据在设备内，离线可用，卸载即彻底删除
  • 完整备份：一键导出数据库，换设备导入即可原样恢复

  • BYOK 直连：AI 请求由你的 Key 直连模型服务商，项目方不接触你的数据
  • 防篡改：App 签名锁定，被二次打包会直接拒绝启动
⚙ 技术实现
用什么
API Key 用 pointycastle 的 AES-256-GCM 加密（密文自描述前缀 + base64）；Android 侧用 flutter_secure_storage 存入系统 Keystore；防篡改通过 MethodChannel 取 APK 真实签名比对；发布构建开启代码混淆。
怎么做
① 加密格式：nonce 12 字节 + 密文 + GCM 认证标签 16 字节，密钥由固定盐经 SHA-256 迭代 1000 轮派生；② 向后兼容回退链：解密依次尝试 当前版本 → 上一版盐 → 旧版算法 → 明文，保证历史数据与改名前的旧备份都能读；③ 备份校验：导入前校验文件魔数、数据库版本号区间、核心表与关键列存在性，防伪造文件；④ 原子恢复：先复制到临时文件二次校验，通过后旧库改名留底再替换，失败自动回滚；⑤ 防篡改 fail-closed：签名校验放在编译期常量比对（不依赖可被清除的本地存储），校验异常一律拒绝启动；⑥ 导出前执行 WAL 检查点，确保拿到一致性的数据库快照。
