## 第 1 步 · 配置 4 个签名 Secrets

**在这之前**：自动发版流水线需要 4 个 Repository Secrets。不配的话项目能正常推送、CI 也能跑，
但**打 tag 发版会失败**（构建 Android 时读不到签名）。

在浏览器打开：
`https://github.com/laow07573-web/daimao-quiz-master/settings/secrets/actions`

逐个新建（名字必须完全一致）：

| Secret 名称 | 值 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | 签名文件的 base64（生成命令见下） |
| `ANDROID_STORE_PASSWORD` | keystore 口令 |
| `ANDROID_KEY_ALIAS` | 密钥别名 |
| `ANDROID_KEY_PASSWORD` | 密钥口令 |

生成 `ANDROID_KEYSTORE_BASE64`（PowerShell，把路径换成你的正式签名文件）：

```powershell
# 注意：-Encoding ascii 会影响输出，这里必须用原始字节转 base64，不要换行
[Convert]::ToBase64String([IO.File]::ReadAllBytes("D:\dev\flashcard_app\android\app\keystore\猫卷_正式签名.jks")) | Set-Clipboard
```

命令执行后 base64 已在剪贴板，直接粘贴进 Secret 的值即可（**不要再落盘成文件**）。

> 口令与别名请从你的离线保管处获取。本仓库任何文件都不应记录它们——
> 此前 `docs/部署与分发指南.md` 曾误记口令，已在本次整改中从当前文件与历史中一并清除。

## 第 2 步 · 推送代码（需要 force-push）

⚠️ **推送前先确认**：本机 `D:\dev\maojuan_private\git_backup_20260914\` 的备份存在且完整
（那是唯一的回滚手段）。

```bash
cd /d/dev/flashcard_app

# 确认当前状态
git log --oneline -3
git status                     # 应为干净

# 1) 推送 main —— 历史已重写，必须 force
git push origin main --force-with-lease

# 2) 推送 tag（历史重写后 tag 对象也变了；tag 指向的提交会一并推送）
git push origin --tags --force
```

> **`master` 不要推**。按本仓库的既有设计，`master` 是完整的本地开发历史
> （逐条提交、含开发过程中的中间状态），`main` 才是对外发布线
> （见 `tools/sync_main.ps1` 头部注释）。这正是不需要 push master 的原因。

> ⚠️ **现在不要先跑 `tools/sync_main.ps1`**。
> 那个脚本是「在远程 main 的最新提交之上」叠一个新提交——如果远程 main 还是旧历史，
> 叠上去的新提交会把旧历史（含参赛材料）一起带回公开仓库。
> **先完成上面第 1 步的 force-push**，把远程 main 换成已清理的历史；
> 之后再要同步新改动，照旧用 `sync_main.ps1` 即可。

> **为什么用 `--force-with-lease` 而不是 `--force`**：前者会在远程有你不知道的新提交时
> 拒绝推送，避免误覆盖别人的工作。

推送完成后，仓库的提交历史里应当**再也搜不到**「项目计划书」「计数草稿」等内容——
在 GitHub 网页搜索，或本地 `git log --all -- docs/` 都应为空。

## 第 5 步 · 验证自动发版流水线（可选，但建议做一次）

用一个预发布 tag 验证整条链路（不会覆盖正式版）：

```bash
cd /d/dev/flashcard_app

# 先把 pubspec.yaml 的 version 临时改成与 tag 一致的预发布号，例如 1.28.2+21
# 注意：tag 与 pubspec 必须一致，否则流水线会主动终止（这是防呆设计）

git tag v1.28.2-rc1
git push origin v1.28.2-rc1
```

预期：触发 **Release** 工作流，产出 4 个产物并创建预发布 Release：

```
MaoJuan-v1.28.2-rc1-android-arm64.apk
MaoJuan-v1.28.2-rc1-android-universal.apk
MaoJuan-v1.28.2-rc1-windows-setup.exe
MaoJuan-v1.28.2-rc1-windows-portable.zip
SHA256SUMS.txt
```

验证完成后删掉这个预发布 Release 与 tag：

```bash
git tag -d v1.28.2-rc1
git push origin :refs/tags/v1.28.2-rc1
```
（Release 在网页上点 Delete 即可）

> 验证通过后，你就可以完全不用本地环境发版了：改 `pubspec.yaml` 的版本 → 提交 →
> 打同名 tag → 推送。剩下的交给流水线。

## 日常发版（本地方式，功能更全）

如果你想保留本地那条链（含四维基线对照与签名校验），仍然用：

```powershell
powershell -ExecutionPolicy Bypass -File tools\publish_release.ps1
```

**版本号只改一处**：`pubspec.yaml` 的 `version:` 字段（形如 `1.29.0+21`）。
其余（应用内展示、README 徽章、推广页版本号与校验值、安装包版本）都会自动跟上；
忘了同步时 `test/version_single_source_test.dart` 会直接报错。

## 出问题时的回滚

如果推送后发现不对，用备份恢复：

```bash
# 把坏掉的仓库挪开，用备份重建（备份是完整的 .git，等价于重写前的状态）
cd /d/dev
move flashcard_app flashcard_app_broken
mkdir flashcard_app
robocopy maojuan_private\git_backup_20260914\.git flashcard_app\.git /E
cd flashcard_app
git reset --hard HEAD      # 恢复工作区
```

远程仓库的回滚需要 force-push 旧提交（在备份里 `git log` 找到即可）。
